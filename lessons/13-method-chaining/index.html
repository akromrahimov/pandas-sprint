02 · Теория

Обработка данных как рецепт

Простыми словами

Представь рецепт плова: «помой рис → обжарь мясо → добавь морковь → засыпь рис → вари 40 минут». Каждый шаг берёт результат предыдущего. Никто не пишет «рис1, рис2, рис3».

  • Цепочка методов (method chaining) — то же самое в pandas: df.шаг1().шаг2().шаг3(). Каждый метод получает таблицу от предыдущего и отдаёт новую.
  • Скобки вокруг всей цепочки ( … ) позволяют писать каждый шаг на отдельной строке. Без них Python не поймёт, что строка, начинающаяся с точки, — продолжение.
  • assign — «добавь колонку». Внутри цепочки пишут lambda d: …: d — это таблица на этом шаге, а не исходная df.
  • query — фильтр, записанный словами: query("status == 'delivered'"). Переменную из кода подставляют через @: query("amount > @porog").
  • pipe — «пропусти таблицу через мою функцию». Так повторяющиеся шаги выносят в функцию с понятным именем.

Ниже два способа посчитать одно и то же: выручку доставленных заказов по категориям. Сравни, какой легче читать.

1. Было: промежуточные переменные. Каждая строка создаёт новую df, их легко перепутать.
df1 = df.dropna(subset=["amount"])
df2 = df1[df1["status"] == "delivered"]
df3 = df2.groupby("category")["amount"].sum()
df4 = df3.sort_values(ascending=False)
df4
category Электроника 609386000.0 Одежда 191719000.0 Дом 189889000.0 Продукты 87059000.0 Красота 70075000.0 Name: amount, dtype: float64

Простыми словами: четыре переменные ради одного ответа. Если в df2 случайно написать df вместо df1, ошибку никто не заметит.

2. Стало: одна цепочка. Читается сверху вниз, как рецепт.
report = (
    df
    .dropna(subset=["amount"])
    .query("status == 'delivered'")
    .groupby("category")["amount"]
    .sum()
    .sort_values(ascending=False)
)
report
category Электроника 609386000.0 Одежда 191719000.0 Дом 189889000.0 Продукты 87059000.0 Красота 70075000.0 Name: amount, dtype: float64

Простыми словами: тот же результат, но каждый шаг — отдельная строка: убрать пустые суммы → оставить доставленные → сгруппировать по категории → сложить → отсортировать.

3. assign + lambda. Новая колонка прямо в цепочке.
(
    df
    .assign(region=lambda d: d["region"].str.strip().str.capitalize(),
            amount_mln=lambda d: (d["amount"] / 1_000_000).round(2))
    ["region"]
    .value_counts()
)
region Ташкент 791 Самарканд 404 Фергана 305 Бухара 265 Наманган 235 Name: count, dtype: int64

Простыми словами: lambda d: значит «возьми таблицу, которая пришла на этот шаг, и посчитай по ней». Было 15 разных написаний региона, после очистки осталось 5.

4. query с переменной. @ подставляет значение из кода.
porog = df["amount"].median()
df.query("amount > @porog and payment == 'card'").shape
(629, 8)

Простыми словами: без @ pandas искал бы колонку с именем porog и выдал ошибку.

По шагам: что происходит с таблицей в цепочке

Цепочку удобно читать вслух, слово «потом» вместо точки: «возьми заказы, потом оставь доставленные, потом раздели по категориям…». На каждом шаге таблица меняется:

  1. dfвсе заказы — строк: 2000, колонок: 8
  2. .dropna(subset=["amount"])убрали заказы без суммы — строк осталось: 1942
  3. .query("status == 'delivered'")оставили доставленные — строк осталось: 1607
  4. .groupby("category")["amount"]разложили заказы по категориям (их 5) — это ещё не ответ, а «стопки» заказов
  5. .sum()в каждой стопке сложили суммы — получилась Series: одно число на категорию
  6. .sort_values(ascending=False)поставили самую большую категорию наверх

Если что-то пошло не так, достаточно найти шаг, после которого строк стало «подозрительно» много или мало (как — в примере 8 ниже).

Что такое lambda

lambda d: d["amount"] / 1_000_000 — это маленькая функция без имени, записанная в одну строку. Читается так: «получи таблицу d и верни d["amount"] / 1 000 000».

Зачем она в assign? В середине цепочки у таблицы нет имени: после .query(...) это уже не исходная df, а новая, отфильтрованная. lambda говорит pandas: «подставь сюда ту таблицу, которая сейчас идёт по цепочке».

5. lambda — это просто короткая функция. Обе записи дают одно и то же.
def to_mln(d):
    return (d["amount"] / 1_000_000).round(2)

a = df.assign(amount_mln=to_mln)["amount_mln"].head(3)
b = df.assign(amount_mln=lambda d: (d["amount"] / 1_000_000).round(2))["amount_mln"].head(3)
print(a.tolist())
print(b.tolist())
[0.37, 0.39, 0.53] [0.37, 0.39, 0.53]

Простыми словами: слева обычная функция с именем, справа lambda без имени. Для одной короткой формулы lambda удобнее: не нужно придумывать имя и писать отдельный def.

6. where: оставить значение только там, где условие верно. Пригодится в задаче 7.
(
    df
    .assign(paid=lambda d: d["amount"].where(d["status"] == "delivered"))
    [["status", "amount", "paid"]]
    .head(5)
)
status amount paid 0 delivered 371000.0 371000.0 1 delivered 387000.0 387000.0 2 delivered 527000.0 527000.0 3 delivered 189000.0 189000.0 4 delivered 188000.0 188000.0

Простыми словами: where(условие) оставляет сумму там, где условие True, а в остальных строках ставит NaN. Так в одной таблице можно считать и все заказы (по order_id), и выручку только доставленных (сумма paid сама пропустит пустые).

03 · Теория

Свои шаги через pipe и как искать ошибку в цепочке

Как читать код с pipe
  • def clean_region(d): — «создаю функцию clean_region, она принимает таблицу d». Внутри — обычные шаги, в конце return отдаёт результат.
  • df.pipe(clean_region) — то же самое, что clean_region(df), но встаёт в цепочку как обычный метод.
  • Чтобы найти ошибку в длинной цепочке, закомментируй нижние шаги (# в начале строки) и запусти: так видно, на каком шаге результат стал неправильным.
7. Свой шаг через pipe. Функцию можно переиспользовать в любом отчёте.
def clean_region(d):
    return d.assign(region=d["region"].str.strip().str.capitalize())

df.pipe(clean_region)["region"].nunique()
5

Простыми словами: функция с понятным названием объясняет шаг лучше любого комментария. В следующем отчёте её достаточно вызвать ещё раз.

8. Подсмотреть размер посередине цепочки.
def show_shape(d, label):
    print(label, d.shape)
    return d

(
    df
    .pipe(show_shape, "всего:")
    .query("status == 'delivered'")
    .pipe(show_shape, "доставлено:")
    .dropna(subset=["amount"])
    .pipe(show_shape, "с суммой:")
    ["amount"].sum()
)
всего: (2000, 8) доставлено: (1661, 8) с суммой: (1607, 8) 1148128000.0

Простыми словами: функция печатает размер и отдаёт таблицу дальше без изменений. Так видно, сколько строк потерялось на каждом шаге.

Правило аналитика. Одна цепочка — один вопрос. Если шагов больше 10–12, раздели цепочку на две с понятными именами: clean = (…) и report = (…).
04 · Ловушки

Пять ошибок в цепочках

1

Нет скобок вокруг цепочки

report = df .query("status == 'delivered'") # SyntaxError
report = (df .query("status == 'delivered'"))

Строка, которая начинается с точки, — ошибка, если вся цепочка не взята в круглые скобки.

2

df вместо d внутри assign

.assign(region_ok=df["region"].str.strip())
.assign(region_ok=lambda d: d["region"].str.strip())

df — исходная таблица, она не знает про предыдущие шаги цепочки. lambda d берёт таблицу именно на этом шаге.

3

inplace=True в цепочке

df.dropna(inplace=True).query(...) # AttributeError: 'NoneType'
df.dropna().query(...)

С inplace=True метод ничего не возвращает (None), и следующему шагу нечего обрабатывать. В цепочках inplace не используют.

4

Забыли @ в query

df.query("amount > porog") # UndefinedVariableError
df.query("amount > @porog")

Без @ pandas ищет колонку с таким именем, а не переменную из кода.

5

Слишком длинная цепочка

Цепочка на 25 шагов так же нечитаема, как простыня с df1…df7. Делай 2–3 цепочки с понятными именами и выноси повторяющиеся шаги в функции через pipe.

Шпаргалка урока: 7 строк, которые надо помнить

  1. (df .шаг1() .шаг2()) — цепочка в скобках, каждый шаг на своей строке
  2. .assign(new=lambda d: d["a"] * 2) — новая колонка по таблице на этом шаге
  3. .query("status == 'delivered'") — фильтр словами
  4. .query("amount > @porog") — переменная из кода
  5. .groupby("a").agg(n=("b", "count")) — агрегация с понятными именами
  6. def step(d): return d… — свой шаг в функции
  7. .pipe(step) — вставить свою функцию в цепочку
05 · Самопроверка · 20 XP

Квиз за 3 минуты

1. Зачем вся цепочка берётся в круглые скобки?

Скобки говорят Python: выражение продолжается на следующих строках. Без них строка, начинающаяся с точки, — синтаксическая ошибка.

2. Что такое d в .assign(x=lambda d: d["a"] * 2)?

lambda получает таблицу, которая пришла на этот шаг, со всеми изменениями предыдущих шагов.

3. Как подставить переменную porog в query?

@ перед именем значит «возьми переменную из кода».

4. Что вернёт df.dropna(inplace=True)?

С inplace=True метод меняет df на месте и возвращает None, поэтому продолжить цепочку нельзя.

5. df.pipe(clean) — это то же самое, что…

pipe просто передаёт таблицу в функцию. Зато так функция встаёт в цепочку как обычный метод.

С чего начать. Функция — это свой шаг цепочки: «получи таблицу, сделай с ней дела, верни результат». Внутри функции такая же цепочка, как вне её. pipe просто передаёт таблицу в твою функцию.

Чем это сделать. .dropna(subset=["amount"]) — убрать строки, где пустая сумма. df.pipe(clean) = clean(df), только внутри цепочки.

Частая ошибка. Не забудь return: без него функция вернёт None, и следующий шаг упадёт.
