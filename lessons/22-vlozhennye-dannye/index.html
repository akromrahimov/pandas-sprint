02 · Теория

JSON и json_normalize

Простыми словами

JSON — это «матрёшка»: внутри заказа лежит клиент, внутри клиента — город. В Python такой заказ выглядит как словарь {"ключ": значение}, а внутри могут быть ещё словари и списки [...].

  • json.load(файл) читает JSON в обычные списки и словари Python.
  • pd.read_json тоже прочитает файл, но вложенный клиент останется в одной ячейке целым словарём — так считать неудобно.
  • pd.json_normalize(orders) «раскрывает матрёшку»: каждое вложенное поле становится своей колонкой с именем через точку — customer.city, delivery.minutes.
  • Списки (блюда, теги) json_normalize не раскрывает — для них есть explode и record_path, это второй раздел.
1. Как выглядит один заказ.
print(len(orders), "заказов")
orders[1]
600 заказов {'order_id': 81001, 'created_at': '2026-10-01 09:39', 'status': 'delivered', 'customer': {'id': 3148, 'city': 'Ташкент', 'vip': False}, 'items': [{'name': 'Лагман', 'category': 'Национальная', 'qty': 2, 'price': 38000}, {'name': 'Бургер', 'category': 'Фастфуд', 'qty': 1, 'price': 32000}], 'tags': ['острое', 'детское'], 'promo': None, 'delivery': {'minutes': 40, 'courier': 'C14'}}

Простыми словами: фигурные скобки — словарь (ключ: значение), квадратные — список. У заказа 81001 два блюда и два тега.

2. read_json: вложенное остаётся в ячейках.
raw = pd.read_json("yetkaz_api.json")
print(raw[["order_id", "customer", "tags"]].head(3))
raw.loc[0, "customer"]["city"]
order_id customer tags 0 81000 {'id': 3033, 'city': 'Наманган', 'vip': False} [] 1 81001 {'id': 3148, 'city': 'Ташкент', 'vip': False} [острое, детское] 2 81002 {'id': 3200, 'city': 'Ташкент', 'vip': True} [] 'Наманган'

Простыми словами: в колонке customer лежат целые словари. Чтобы достать город, приходится лезть внутрь каждой ячейки — неудобно и медленно.

3. json_normalize: каждое вложенное поле — своя колонка.
flat = pd.json_normalize(orders)
print(flat.columns.tolist())
flat[["order_id", "customer.city", "customer.vip", "delivery.minutes"]].head(3)
['order_id', 'created_at', 'status', 'items', 'tags', 'promo', 'customer.id', 'customer.city', 'customer.vip', 'delivery.minutes', 'delivery.courier'] order_id customer.city customer.vip delivery.minutes 0 81000 Наманган False 44 1 81001 Ташкент False 40 2 81002 Ташкент True 23

Простыми словами: из словарей customer и delivery получились обычные колонки. Колонки items и tags остались списками — их раскрываем дальше.

03 · Теория

Списки в ячейках: explode и record_path

Как раскрыть список

Представь чек, где в одной строке записано «плов, чай, самса». Чтобы посчитать, сколько продали чая, нужно разрезать чек: одна строка — одна позиция.

  • explode("tags") — каждый элемент списка в отдельную строку. Остальные колонки повторяются. Пустой список превращается в NaN.
  • .str.len() работает и со списками: сколько в нём элементов.
  • Если элементы списка сами словари (блюда), удобнее pd.json_normalize(orders, record_path="items", meta=[...]): одна строка — одно блюдо, а из meta к каждой строке приклеятся нужные поля заказа.
4. explode: теги по одному в строке.
t = flat[["order_id", "tags"]].head(4)
print(t)
print()
t.explode("tags")
order_id tags 0 81000 [] 1 81001 [острое, детское] 2 81002 [] 3 81003 [] order_id tags 0 81000 NaN 1 81001 острое 1 81001 детское 2 81002 NaN 3 81003 NaN

Простыми словами: у заказа с двумя тегами стало две строки, у заказа без тегов — одна строка с NaN. Номер заказа повторился в каждой строке.

5. Какие пожелания пишут чаще всего.
print(round((flat["tags"].str.len() > 0).mean() * 100, 1), "% заказов с тегами")
flat["tags"].explode().value_counts()
60.0 % заказов с тегами tags детское 107 острое 102 без лука 85 подарок 84 вегетарианское 82 Name: count, dtype: int64

Простыми словами: value_counts сам не считает пустые (NaN) значения, поэтому заказы без тегов в подсчёт не попали. Чаще всего пишут «детское».

6. record_path: таблица блюд с полями заказа.
items = pd.json_normalize(orders, record_path="items", meta=["order_id", "status", ["customer", "city"]])
print(len(items), "строк-блюд")
items.head(4)
1225 строк-блюд name category qty price order_id status customer.city 0 Плов Национальная 1 45000 81000 delivered Наманган 1 Лагман Национальная 2 38000 81001 delivered Ташкент 2 Бургер Фастфуд 1 32000 81001 delivered Ташкент 3 Чай Напитки 1 6000 81002 delivered Ташкент

Простыми словами: record_path="items" — «разверни список items». meta — какие поля заказа приклеить к каждому блюду; путь внутрь вложенного словаря пишут списком: ["customer", "city"].

04 · Теория

map, apply, where и mask

Когда готовой функции нет
  • s.map(словарь) — заменить каждое значение по словарю: delivered → «доставлен». Чего нет в словаре — станет NaN.
  • s.map(функция) или s.apply(функция) — применить свою функцию к каждому значению. Удобно для списков и словарей внутри ячеек.
  • s.where(условие) — оставить значение, где условие True, остальное заменить на NaN (или на то, что укажешь). s.mask(условие) — наоборот: спрятать, где условие True.
  • apply построчно — медленный путь: pandas вызывает функцию для каждой строки по очереди. Если есть готовая функция (сумма, сравнение, .str), бери её — подробнее в уроке 24.
7. map по словарю.
ru = {"delivered": "доставлен", "cancelled": "отменён"}
flat["status"].map(ru).value_counts()
status доставлен 551 отменён 49 Name: count, dtype: int64

Простыми словами: каждое английское значение заменилось русским. Отменено 8,2% заказов.

8. Своя функция для списка в ячейке. Сумма заказа прямо из списка блюд.
def order_sum(items):
    return sum(i["qty"] * i["price"] for i in items)

flat["items"].apply(order_sum).head(3)
0 45000 1 108000 2 16000 Name: items, dtype: int64

Простыми словами: функция получает список блюд одного заказа и возвращает сумму. apply вызывает её для каждого заказа. То же самое можно посчитать через таблицу блюд и groupby — так и сделаем в задаче 5.

9. where и mask. Время доставки имеет смысл только у доставленных заказов.
m = flat["delivery.minutes"]
delivered_min = m.where(flat["status"] == "delivered")      # у отменённых → NaN
capped = m.mask(m > 60, 60)                                  # больше 60 → 60
rows = [0, (flat["status"] == "cancelled").idxmax(), (m > 60).idxmax()]   # обычный, отменённый, долгий
pd.DataFrame({"status": flat["status"], "minutes": m, "where": delivered_min, "mask": capped}).loc[rows]
status minutes where mask 0 delivered 44 44.0 44 36 cancelled 32 NaN 32 10 delivered 63 63.0 60

Простыми словами: .idxmax() у маски True/False находит первую строку, где True. where оставил минуты только у доставленных заказов, а у отменённого поставил NaN — среднее по городу не испортится. mask заменил время больше 60 минут на 60.

05 · Ловушки

Пять ловушек вложенных данных

1

Подсчёт людей после explode

flat.explode("tags")["order_id"].count() # заказ с 2 тегами посчитан дважды
flat["order_id"].nunique()

После explode строки повторяются. Число заказов считай до explode или через nunique.

2

Пустой список стал NaN

explode превращает пустой список в строку с NaN. Если нужна доля заказов с тегами, считай по исходной колонке: flat["tags"].str.len() > 0.

3

map без нужного ключа

Значение, которого нет в словаре, превратится в NaN. Проверь s.map(d).isna().sum() или используй s.map(d).fillna(s), чтобы оставить неизвестные как есть.

4

apply там, где есть готовая функция

items.apply(lambda r: r["qty"] * r["price"], axis=1) # медленно
items["qty"] * items["price"]

Построчный apply в десятки раз медленнее обычной арифметики над колонками. apply оставляй для списков, словарей и сложной логики.

5

Средние с мусорными значениями

У отменённых заказов время доставки бессмысленно. Перед средним спрячь такие значения через where или отфильтруй строки.

Шпаргалка урока: вложенные данные

  1. with open(f, encoding="utf-8") as fh: orders = json.load(fh) — прочитать JSON в Python
  2. pd.json_normalize(orders) — вложенные поля → колонки через точку
  3. pd.json_normalize(orders, record_path="items", meta=["order_id", ["customer", "city"]]) — список словарей → строки
  4. flat.explode("tags") — список → по элементу в строке
  5. flat["tags"].str.len() — сколько элементов в списке
  6. s.map({"a": "б"}) / s.apply(func) — замена по словарю / своя функция
  7. s.where(cond) / s.mask(cond, value) — оставить по условию / спрятать по условию
06 · Самопроверка · 20 XP

Квиз за 3 минуты

1. Что делает pd.json_normalize(orders)?

customer.city, delivery.minutes — каждое вложенное поле становится колонкой. Списки при этом остаются списками.

2. В ячейке список из трёх тегов. Сколько строк будет после explode?

Каждый элемент списка получает свою строку, остальные колонки повторяются.

3. Что вернёт s.map({"a": 1}) для значения "b"?

Значения, которых нет в словаре, превращаются в NaN.

4. Чем where отличается от mask?

Это зеркальные функции: where(cond) = mask(~cond).

5. Когда стоит использовать apply?

apply вызывает функцию для каждого значения по очереди и работает медленно, зато справляется со списками и словарями в ячейках.
