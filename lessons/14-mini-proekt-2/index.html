02 · Теория

Восемь шагов от трёх файлов до отчёта

Как устроен проект

Каждая задача — один шаг проекта. Перед задачей уже выполнены все предыдущие шаги (их код можно раскрыть под условием), поэтому таблицы cust, full и другие появляются по ходу работы.

  • Шаги 1–2. Осмотр и очистка справочника клиентов: повторы, город.
  • Шаги 3–4. Соединение: заказы + товары (цена) → выручка; + клиенты (сегмент, город). Проверяем, что строк не стало больше.
  • Шаги 5–7. Выручка по сегментам, сводная «сегмент × категория», города.
  • Шаг 8. Итоговая сводка в одной Series — как паспорт данных из урока 1.

Три приёма из недели 2, которые сегодня понадобятся. Каждый вывод получен настоящим запуском pandas.

1. Ключ уникален? Перед соединением проверь справочник.
print(customers["customer_id"].is_unique, customers["customer_id"].duplicated().sum())
False 15

Простыми словами: False и 15: у 15 клиентов по две строки. Если соединить заказы с таким справочником, заказы этих клиентов удвоятся.

2. Что будет при «наивном» соединении.
print(len(orders))
print(len(orders.merge(customers, on="customer_id")))
3000 3016

Простыми словами: строк стало 3016 вместо 3 000: часть заказов задвоилась (повторы в справочнике), а часть пропала (клиентов нет в справочнике). Две ошибки частично гасят друг друга — поэтому выручка «почти сходится» и ошибку трудно заметить.

3. validate и indicator — страховка.
check = orders.merge(products, on="product_id", how="left", validate="many_to_one", indicator=True)
check["_merge"].value_counts()
_merge both 3000 left_only 0 right_only 0 Name: count, dtype: int64

Простыми словами: validate="many_to_one" упадёт с ошибкой, если в правой таблице ключ не уникален. indicator=True добавляет колонку _merge: both — нашлась пара, left_only — пары нет.

Правило проекта. После каждого merge сравни число строк до и после. Если стало больше — в правой таблице повторы ключа. Если какие-то строки без пары — посчитай, сколько денег на них приходится.
03 · Ловушки

Четыре ловушки этого проекта

1

Справочник с повторами ключа

full = orders.merge(customers, on="customer_id") # строк стало больше
cust = customers.drop_duplicates("customer_id", keep="last") full = orders.merge(cust, on="customer_id", how="left", validate="many_to_one")

Сначала убери повторы в справочнике, потом соединяй. validate сразу скажет, если повторы остались.

2

inner вместо left

orders.merge(cust, on="customer_id") # 40 заказов молча исчезли
orders.merge(cust, on="customer_id", how="left", indicator=True)

По умолчанию merge оставляет только строки с парой (inner). Заказы клиентов, которых нет в справочнике, пропадут вместе с их деньгами.

3

Выручка по всем статусам

Отменённые и возвращённые заказы денег не принесли. Выручку считай только по status == "delivered", а долю отмен — по всем заказам.

4

Доля клиентов ≠ доля денег

VIP может быть всего 13,9% клиентов, но заметная доля выручки. Всегда показывай обе доли рядом, иначе вывод будет неверным.

Шпаргалка проекта

  1. df["key"].is_unique — ключ без повторов?
  2. drop_duplicates("key", keep="last") — оставить последнюю версию записи
  3. merge(..., how="left", validate="many_to_one") — соединение со страховкой
  4. merge(..., indicator=True) — колонка _merge: нашлась ли пара
  5. groupby("a")["revenue"].sum() / total — доля в общей сумме
  6. pd.pivot_table(df, index=..., columns=..., values=..., aggfunc="sum") — сводная таблица
  7. pd.Series({...}) — итоговая сводка для руководителя
04 · Самопроверка · 20 XP

Квиз за 3 минуты

1. В справочнике клиентов ключ повторяется у 15 человек. Что будет при merge заказов с ним?

Каждый заказ соединится с обеими строками клиента, и заказ появится дважды. Ошибку даст только validate.

2. Что значит _merge == "left_only"?

left_only — для строки левой таблицы не нашлось пары в правой. Для заказов это клиенты, которых нет в справочнике.

3. Как по умолчанию соединяет merge?

По умолчанию how="inner": остаются только строки, у которых нашлась пара в обеих таблицах.

4. Выручку по сегментам считают по…

Отменённые и возвращённые заказы денег не принесли.

5. Сегмент — 14% клиентов и 25% выручки. Что это значит?

Доля денег больше доли людей — значит, каждый VIP в среднем приносит больше. Обе доли надо показывать рядом.
