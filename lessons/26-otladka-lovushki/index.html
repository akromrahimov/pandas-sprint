Отладка и ловушки: тихие ошибки

Самые опасные ошибки в анализе — не те, после которых код падает, а те, после которых он спокойно выдаёт неправильные цифры. Изменение, которое не сохранилось. Пустые клетки, которые «прошли» фильтр. 02 · Теория

Изменение, которое не сохранилось

Простыми словами

Представь, что ты взял ксерокопию документа и исправил ошибку на копии. Оригинал остался с ошибкой. В pandas 3.0 то же самое: tx[маска] — это новая таблица-копия, и запись в неё не меняет tx. Это правило называется Copy-on-Write («копия при записи»).

  • Не работает: tx[tx["status"] == "declined"]["amount"] = 0 — две пары скобок подряд, запись в копию.
  • Работает: tx.loc[tx["status"] == "declined", "amount"] = 0 — один .loc со строками и колонкой.
  • pandas 3.0 предупреждает о такой записи (ChainedAssignmentError), но предупреждение легко не заметить.
1. Запись в копию.
t = tx.copy()
print(t["amount"].isna().sum())
t[t["amount"].isna()]["amount"] = 0      # пишем в копию — t не изменится
print(t["amount"].isna().sum())
t.loc[t["amount"].isna(), "amount"] = 0  # правильно
print(t["amount"].isna().sum())
18 18 0

Простыми словами: после первой попытки пустых по-прежнему 18 — изменение ушло в копию. После .loc пустых 0.

03 · Теория

Как ведут себя пустые значения

Правила NaN, которые надо помнить
  • NaN != "UZ" — True. Поэтому фильтр «не равно» пропускает пустые клетки.
  • NaN == NaN — False. Пустые ищут только через isna().
  • sum() и mean() молча пропускают NaN. Если заменить NaN на 0, среднее станет меньше.
  • size() считает все строки, count() — только непустые.
2. «Не равно» и пустые.
print((tx["country"] != "UZ").sum())
print((tx["country"].notna() & (tx["country"] != "UZ")).sum())
213 186

Простыми словами: разница 27 — это транзакции без страны, которые наивный фильтр посчитал иностранными.

3. Среднее с пропусками и с нулями.
print(round(tx["amount"].mean()), round(tx["amount"].fillna(0).mean()))
1098531 1085349

Простыми словами: заполнив пустые суммы нулём, мы «нашли» 18 транзакций по 0 сум, которых не было, и среднее уменьшилось.

04 · Теория

Соединение, которое удвоило деньги

Как ловить ошибки заранее
  • Если в правой таблице ключ повторяется, merge размножит строки левой. Деньги «вырастут», хотя новых платежей не было.
  • validate="many_to_one" — merge сам упадёт с понятной ошибкой, если в правой таблице есть повторы ключа.
  • assert условие, "сообщение" — «проверь, что условие верно, иначе останови код с этим сообщением». Это сигнализация для данных: лучше упасть, чем отдать неверные цифры.
4. Взрыв джойна на игрушечном примере. Два платежа и справочник, где один человек записан дважды.
p2 = pd.DataFrame({"user_id": [1, 2], "amount": [100, 50]})
u2 = pd.DataFrame({"user_id": [1, 1, 2], "plan": ["basic", "pro", "basic"]})   # у человека 1 две записи
j = p2.merge(u2, on="user_id", how="left")
print(j)
print("денег было:", p2["amount"].sum(), "— после соединения:", j["amount"].sum())
user_id amount plan 0 1 100 basic 1 1 100 pro 2 2 50 basic денег было: 150 — после соединения: 250

Простыми словами: платёж человека 1 нашёл в справочнике две пары и превратился в две строки. Денег «стало» 250 вместо 150, хотя новых платежей не было. Так и появляется лишняя выручка в отчёте.

5. Строк стало больше. То же на настоящих данных.
joined = pay.merge(users, on="user_id", how="left")
print(len(pay), len(joined))
print(users["user_id"].duplicated().sum())
1261 1309 24

Простыми словами: платежей 1261, а после соединения 1309 строк: у 24 пользователей в справочнике по две записи.

6. assert ловит ошибку до отчёта.
try:
    assert users["user_id"].is_unique, "в справочнике пользователей повторяется user_id"
except AssertionError as e:
    print("Проверка не прошла:", e)
Проверка не прошла: в справочнике пользователей повторяется user_id

Простыми словами: assert остановил бы скрипт с понятным сообщением. try … except значит «попробуй выполнить; если случится такая-то ошибка — не падай, а сделай вот это». Здесь он нужен только для примера — чтобы показать текст ошибки, а не остановить страницу.

7. Функция-чеклист для данных. Каждая строка — одна проверка. Приём для задачи 7.
def quick_check(d):
    return pd.Series({
        "строк": len(d),
        "полных дублей": d.duplicated().sum(),
        "пустых сумм": d["amount"].isna().sum(),
        "сумм ≤ 0": (d["amount"] <= 0).sum(),
    })

quick_check(tx)
строк 1500 полных дублей 0 пустых сумм 18 сумм ≤ 0 0 dtype: int64

Простыми словами: одна функция собирает главные проверки в Series. Её запускают перед каждым отчётом: если где-то не ноль, сначала разбираются с данными. Обрати внимание: пустые суммы и «сумма ≤ 0» считаются отдельно — сравнение с NaN всегда даёт False.

Правило аналитика. Перед каждым отчётом запускай проверки: число строк, уникальность ключей, пустые значения, допустимые значения статусов. Пять строк проверок экономят часы поиска ошибок потом.
05 · Ловушки

Пять тихих ошибок

1

Двойные скобки для записи

df[df["a"] > 0]["b"] = 1 # ничего не изменилось
df.loc[df["a"] > 0, "b"] = 1

Копия при записи (Copy-on-Write) в pandas 3.0: запись через цепочку скобок уходит в копию.

2

!= с пустыми

df[df["country"] != "UZ"]
df[df["country"].notna() & (df["country"] != "UZ")]

NaN != что угодно — True. Пустые значения проходят фильтр «не равно».

3

fillna(0) перед средним

Пустая клетка — «не знаем», а не «ноль». Заполнение нулём занижает средние и медианы.

4

Повторы ключа в справочнике

merge с таким справочником размножает строки. Всегда проверяй is_unique и ставь validate.

5

Проверка глазами

«Вроде похоже на правду» — не проверка. Сверяй итог с независимым числом: общей суммой из бухгалтерии, числом строк до и после.

Шпаргалка урока: защита от тихих ошибок

  1. df.loc[маска, "col"] = значение — изменение, которое сохранится
  2. s.notna() & (s != "x") — «не равно» без пустых
  3. s.isna().sum() — сколько пустых
  4. groupby(...).size() vs .count() — все строки и непустые
  5. merge(..., validate="many_to_one") — защита от размножения строк
  6. assert df["id"].is_unique, "сообщение" — проверка с остановкой
  7. assert len(after) == len(before) — строк не стало больше
  8. s[~s.isin(allowed)] — недопустимые значения
06 · Самопроверка · 20 XP

Квиз за 3 минуты

1. Что произойдёт после df[df["a"] > 0]["b"] = 1 в pandas 3.0?

Запись идёт в копию (Copy-on-Write), исходная df остаётся прежней.

2. Чему равно np.nan != "UZ"?

Любое «не равно» с NaN даёт True.

3. Чем count() отличается от size() в groupby?

size — все строки группы, count — только непустые значения колонки.

4. После merge строк стало больше, чем было в левой таблице. Почему?

Каждая строка левой таблицы соединилась с несколькими строками правой.

5. Что делает assert len(a) == len(b), "строк стало больше"?

assert — проверка: если условие ложно, выполнение прерывается с AssertionError и текстом сообщения.

print("___")

Частая ошибка. Сообщение пишется через запятую после условия, а не в скобках: assert(усл, "текст") всегда «правда».

С чего начать. Функция-чеклист: каждое число — одна простая проверка, которую ты уже делал в курсе (дубли, повторы ключа, пустые, недопустимые значения, грязный текст). Собери их в одну Series.

Чем это сделать. Недопустимый статус: ~df["status"].isin([...]). Грязный город — тот, что меняется после чистки: df["city"] != df["city"].str.strip().str.capitalize().

Шаблон — замени ___ своим:
def validate_tx(df):
    return pd.Series({
        "rows": len(df),
        "dup_rows": df.___().sum(),
        "dup_tx_id": df["tx_id"].___().sum(),

        "bad_amount": (df["amount"] ___ 0).sum(),

Частая ошибка. bad_amount — суммы ≤ 0, а пустые суммы считаются отдельно (сравнение с NaN даёт False и сюда не попадёт).
