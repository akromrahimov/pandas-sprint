02 · Теория

Почему «Ташкент» ≠ « Ташкент»

Простыми словами

Представь, что в классе собирают подписи на открытку. Один написал «Али», другой «АЛИ», третий « али» с пробелом впереди. Учитель сразу видит: это один мальчик. А компьютер сравнивает буквы по одной, как замок с кодом: одна лишняя буква или пробел — и код «не тот». Для него это три разных человека.

  • Строка (str) — текст в ячейке. В pandas 3.0 у текстовых колонок тип str.
  • .str — «волшебная дверь» к текстовым методам. df["city"].str.lower() значит: «для каждой строки колонки сделай lower». Без .str pandas не поймёт, что ты хочешь работать с буквами.
  • strip() — срезать пробелы по краям (TRIM). lower() — все буквы маленькие (LOWER).
  • replace("г. ", "") — найти кусок текста и заменить (REPLACE).
  • contains("iphone", case=False) — «есть ли внутри это слово?», True/False (LIKE '%iphone%'). case=False — не обращать внимания на большие и маленькие буквы.
  • Регулярное выражение (regex) — шаблон поиска. \D значит «любой знак, который НЕ цифра». \s+ — «один или больше пробелов подряд».

Главная мысль дня: сначала приведи текст к одному виду, потом считай. Иначе value_counts, nunique и любые доли делят одного продавца или один город на куски.

03 · Теория

Семь приёмов: почистить, найти, вытащить число

Как читать код
  • df["seller_city"].str.strip().str.lower() — точка = «потом». Взяли колонку → открыли текстовые методы (.str) → срезали пробелы → снова .str → сделали маленькие буквы. После каждого метода получается новая Series, поэтому .str пишем заново.
  • .str.replace("г. ", "", regex=False) — первое в скобках: что ищем; второе: на что меняем (пустая строка = удалить). regex=False: точку понимать как обычную точку, а не шаблон.
  • .replace(latin) — БЕЗ .str: меняет значение ячейки целиком по словарю {"было": "стало"}. С .str меняет кусок внутри текста.
  • r"\D" — буква r перед кавычками значит «сырая строка»: обратную косую черту не трогать. \D — любой НЕ-цифровой знак. Заменили все такие на "" — остались только цифры.
  • pd.to_numeric(..., errors="coerce") — превратить текст в число; coerce («заставить»): если не получается — поставить NaN, а не падать с ошибкой.
  • .str[-9:] — как срез у обычной строки: последние 9 знаков. .str.len() — сколько знаков в каждой строке.
  • .str.extract(r"(samsung|iphone)", expand=False) — круглые скобки = «что достать», | = «или». Нет совпадения — NaN. expand=False — вернуть Series, а не таблицу.

Каждый вывод ниже получен реальным запуском pandas 3.0 на файле BozorMarket. Твои цифры должны совпасть.

3. str.contains — LIKE и ILIKE.
print(df["title"].str.contains("iPhone").sum(),

Простыми словами: contains на каждую строку отвечает True/False, а .sum() считает True. С учётом регистра — 317, без учёта — 355: 38 объявлений написаны «iphone» или «IPHONE». Но и 355 — это не «телефоны iPhone»: смотри следующую карточку.

7. str.extract — достать бренд по шаблону.
title = df["title"].str.strip().str.lower()

Простыми словами: extract ищет внутри каждой строки первое слово из списка и возвращает его. Казан (строка 2) не Samsung, не iPhone и не Xiaomi — поэтому NaN. Бренд стоит в разных местах названия, поэтому «взять второе слово» не работает, а шаблон — работает.

История про подписи: 4 мальчика или 2?

На открытке четыре подписи: «Али», « Али», «али» и «Самир». Сколько детей подписалось? Глазами — двое. Компьютер скажет 4: пробел и маленькая буква делают «новое» имя. После strip + lower остаются «али», «али», «али», «самир» — 2 разных.

до чистки: 4 «разных» именипосле strip + lower: 2
s = pd.Series(["Али", " Али", "али", "Самир"])
print(s.nunique(), s.str.strip().str.lower().nunique())   # 4 2

Так и у Камилы: 852 «продавца» — это 259 человек, записанных по-разному. Правило: перед nunique, value_counts и долями по тексту — всегда чистка.

Бонус. to_numeric без чистки ломает почти всё.
print(pd.to_numeric(df["price_raw"], errors="coerce").isna().sum())
print(pd.to_numeric(pd.Series(["461.000"])))
1053 0 461.0 dtype: float64

Простыми словами: без чистки 1 053 из 1 400 цен стали NaN — coerce молча выкинул всё с пробелами и «сум». А «461.000» (так пишут 461 тысячу) pandas прочитал как 461.0 — точка для него десятичная. Цена казана упала бы в 1 000 раз, и ошибки ты бы не увидел. Поэтому выкидываем ВСЕ не-цифры, включая точку.

Правило аналитика. Прежде чем считать по текстовой колонке, посмотри value_counts() целиком. Если видишь «почти одинаковые» значения — сначала чистка, потом метрики.
04 · Ловушки

Пять ошибок, на которых спотыкается большинство

1

Метод без .str

df["seller_city"].lower() # AttributeError: 'Series' object has no attribute 'lower'
df["seller_city"].str.lower()

Текстовые методы живут за дверью .str. И после каждого шага цепочки .str пишем заново.

2

contains без case=False

df["title"].str.contains("iphone").sum() # пропустит «iPhone» и «IPHONE»
df["title"].str.contains("iphone", case=False).sum() # 355

Как LIKE против ILIKE. Если не уверен в регистре — case=False.

3

strip не трогает пробелы внутри

"чехол для iphone".strip() # «чехол для iphone» — двойной пробел остался
s.str.strip().str.replace(r"\s+", " ", regex=True)

strip чистит только края. Внутри — replace по шаблону \s+.

4

to_numeric по грязному тексту

pd.to_numeric(df["price_raw"], errors="coerce") # 1053 NaN, «461.000» → 461.0
pd.to_numeric(df["price_raw"].str.replace(r"\D", "", regex=True), errors="coerce")

coerce молчит: не падает, а тихо делает NaN. После него всегда проверяй isna().sum().

5

Считать товар по слову в названии

df["title"].str.contains("iphone", case=False).sum() # 355 — с чехлами и стёклами
df["category"].str.contains("смартфоны", case=False).sum() # 620 смартфонов

Слово в названии ≠ тип товара. Для «сколько смартфонов» используй категорию.

Шпаргалка урока: 8 строк, которые надо помнить

  1. s.str.strip().str.lower() — TRIM + LOWER
  2. s.str.replace("г. ", "", regex=False) — REPLACE куска текста
  3. s.replace({"tashkent": "ташкент"}) — заменить значение целиком (без .str)
  4. s.str.replace(r"\s+", " ", regex=True) — двойные пробелы внутри → один
  5. s.str.contains("iphone", case=False) — ILIKE '%iphone%', маска True/False
  6. pd.to_numeric(s.str.replace(r"\D", "", regex=True), errors="coerce") — число из текста
  7. s.str[-9:] / s.str.len() — RIGHT(s, 9) / LENGTH(s)
  8. s.str.extract(r"(samsung|xiaomi)", expand=False) — достать слово по шаблону
05 · Самопроверка · 20 XP

Квиз за 3 минуты

1. Почему df["seller_city"].lower() падает с ошибкой?

Текстовые методы колонки живут за «дверью» .str: df["seller_city"].str.lower().

2. str.contains("iPhone").sum() = 317, а с case=False = 355. Что верно?

Как LIKE против ILIKE. И даже 355 — не смартфоны: там 204 чехла и стекла. Смартфоны считаем по категории.

3. Что вернёт pd.to_numeric(pd.Series(["461.000"]))?

Для pandas точка — десятичный разделитель. Поэтому сначала убираем ВСЕ не-цифры: str.replace(r"\D", "", regex=True).

4. Чем отличается s.str.replace("г. ", "") от s.replace({"tashkent": "ташкент"})?

«г. Ташкент» → «Ташкент» — кусок (.str.replace). «tashkent» → «ташкент» — значение целиком (replace со словарём).

5. Названия: «чехол для iphone» (два пробела) и «чехол для iphone». Что сделает их одинаковыми?

strip чистит только края. Пробелы внутри схлопывает шаблон \s+ («один или больше пробелов») → один пробел.

💡 Подсказка

С чего начать. «Ташкент», « Ташкент» и «ташкент» для pandas — три разных города. Приведи текст к одному виду: убери пробелы по краям и сделай все буквы маленькими. Потом сравни, сколько разных значений было и стало.

Чем это сделать. Текстовые методы колонки пишутся через .str: .str.strip() — убрать пробелы по краям, .str.lower() — маленькие буквы. Их можно ставить цепочкой.

Шаблон — замени ___ своим:
city = df["seller_city"].str.___().str.___()
print(df["seller_city"].nunique(), city.___())
print(city.value_counts().head(___))

Частая ошибка. Без .str будет ошибка: df["city"].lower() — у колонки нет такого метода, он есть у её текста.
