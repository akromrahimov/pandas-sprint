Даты: to_datetime и .dt

Почти в любой выгрузке есть даты: когда создан заказ, когда доставлен, когда клиент зарегистрировался. Но pandas читает их как обычный текст, и с текстом нельзя посчитать «сколько часов шла доставка» или «сколько заказов в выходные». Сегодня учимся превращать текст в настоящие даты и доставать из них месяц, день недели и разницу во времени.

02 · Теория

Почему дата из файла — это ещё не дата

Простыми словами

Для pandas строка «2026-07-03 14:22» — просто набор символов, как «привет». Её нельзя сравнить с другой датой по смыслу, из неё нельзя достать месяц, а «минус» между двумя такими строками даёт ошибку.

  • pd.to_datetime(колонка) — «прочитай этот текст как дату и время». Тип колонки станет datetime64.
  • format — подсказка, как записана дата: "%Y-%m-%d %H:%M" значит «год-месяц-день часы:минуты». %d.%m.%Y — «день.месяц.год».
  • errors="coerce" — «если не получилось прочитать — поставь пустую дату (NaT), а не падай с ошибкой».
  • NaT (Not a Time) — пустая клетка для дат, как NaN для чисел.
  • Разница двух дат — это промежуток времени (Timedelta): «2 дня 3 часа». Перевести в часы: .dt.total_seconds() / 3600.

Пример из жизни: «03.07» для человека — третье июля, а для компьютера это может быть и 7 марта. Поэтому дату нужно один раз «объяснить» pandas, и дальше он будет понимать её правильно.

Шпаргалка по format: как описать запись даты

Каждый кусочек даты обозначается знаком % и буквой. Между ними пишешь те же разделители, что в файле (дефис, точку, пробел, двоеточие).

ЗнакЧто значитПример
%Yгод, 4 цифры2026
%mмесяц, 2 цифры07
%dдень, 2 цифры03
%Hчасы (0–23)14
%Mминуты22

«2026-07-03 14:22» → "%Y-%m-%d %H:%M", а «03.07.2026 14:22» → "%d.%m.%Y %H:%M". Внимание: маленькая m — месяц, большая M — минуты.

2. Два формата в одной колонке. Читаем первым форматом и смотрим, что не прочиталось.

Простыми словами: 150 пустых: 90 посылок ещё в пути, а ещё 60 дат записаны как «день.месяц.год». errors="coerce" не уронил код, а показал проблему.

3. Склеиваем два формата. fillna берёт значение из второй попытки там, где первая пустая.

Простыми словами: осталось 90 пустых — это честные «ещё в пути». Все даты доставки прочитаны.

03 · Теория

Части даты и время между событиями

Как читать код с .dt
  • .dt — «у колонки с датами достань…»: .dt.month — месяц (1–12), .dt.hour — час, .dt.dayofweek — день недели (0 = понедельник, 6 = воскресенье).
  • .dt.to_period("M") — «округли до месяца»: 2026-07-03 → 2026-07. Удобно для отчётов по месяцам.
  • Даты можно сравнивать с текстом-датой: df[df["created"] >= "2026-09-01"].
4. Анатомия одной даты. Что можно достать из даты первой посылки.
t = df["created"].iloc[0]
pd.Series({
    "дата целиком": t,
    "год": t.year,
    "месяц": t.month,
    "день": t.day,
    "час": t.hour,
    "день недели (0 = пн)": t.dayofweek,
    "название дня": t.day_name(),
    "месяц-период": t.to_period("M"),
})
дата целиком 2026-08-28 03:52:00 год 2026 месяц 8 день 28 час 3 день недели (0 = пн) 4 название дня Friday месяц-период 2026-08 dtype: object

Простыми словами: у одной даты эти части достаются через точку: t.month. У целой колонки — через .dt: df["created"].dt.month даёт месяц для каждой строки сразу.

5. Разница дат по шагам. Три посылки: когда создали, когда доставили, сколько прошло.
(

    .assign(разница=lambda d: d["delivered"] - d["created"],
            часов=lambda d: ((d["delivered"] - d["created"]).dt.total_seconds() / 3600).round(1))
    [["created", "delivered", "разница", "часов"]]
    .head(3)
)
created delivered разница часов 0 2026-08-28 03:52:00 2026-08-29 00:06:00 0 days 20:14:00 20.2 1 2026-07-01 17:40:00 2026-07-02 03:01:00 0 days 09:21:00 9.4 2 2026-07-14 15:52:00 2026-07-15 03:26:00 0 days 11:34:00 11.6

Простыми словами: вычитание дат даёт промежуток: «0 days 20:14:00» значит 0 дней 20 часов 14 минут. Считать с таким видом неудобно, поэтому переводим его в одно число: всего секунд / 3 600 = часы (20,2).

6. Сколько часов идёт посылка.
df["hours"] = (df["delivered"] - df["created"]).dt.total_seconds() / 3600
df["hours"].describe().round(1)
count 1710.0 mean 27.9 std 19.2 min 1.8 25% 14.9 50% 23.5 75% 36.2 max 182.7 Name: hours, dtype: float64

Простыми словами: разница дат — промежуток времени; делим секунды на 3 600 и получаем часы. Медиана (50%) — типичное время доставки, max показывает самые долгие случаи.

7. Посылки по месяцам.
df["created"].dt.to_period("M").value_counts().sort_index()
created 2026-07 581 2026-08 619 2026-09 600 Freq: M, Name: count, dtype: int64

Простыми словами: to_period("M") превращает каждую дату в «год-месяц». sort_index() ставит месяцы по порядку, а не по количеству.

8. Будни или выходные.
weekend = df["created"].dt.dayofweek >= 5
print(weekend.mean().round(3))
df.groupby(weekend)["hours"].median().round(1)
0.272 created False 21.1 True 30.0 Name: hours, dtype: float64

Простыми словами: dayofweek 5 и 6 — суббота и воскресенье. В группировке False — будни, True — выходные: видно, что в выходные медиана заметно больше.

9. Свой срок для каждой строки. Приём для задачи 5: лимит зависит от типа доставки.
done = df[df["delivered"].notna()].copy()
done["limit"] = np.where(done["service"] == "express", 24, 48)
done["late"] = done["hours"] > done["limit"]
done[["service", "hours", "limit", "late"]].head(4).round(1)
service hours limit late 0 express 20.2 24 False 1 express 9.4 24 False 2 standard 11.6 48 False 3 standard 19.2 48 False

Простыми словами: np.where ставит 24 часа экспрессу и 48 остальным. Потом каждую посылку сравниваем с её лимитом. .copy() делает отдельную таблицу: без него pandas предупредит, что ты меняешь «кусок» другой таблицы.

Правило аналитика. После to_datetime всегда смотри на min, max и число пустых дат. Дата «1970-01-01» или «2099» — признак ошибки в данных, а большое число NaT — признак другого формата.
04 · Ловушки

Пять ловушек с датами

1

Считать по тексту

df["delivered_at"] - df["created_at"] # TypeError: строки не вычитаются
pd.to_datetime(df["delivered_at"]) - pd.to_datetime(df["created_at"])

Пока колонка — текст, никакой арифметики с датами нет.

2

Несколько форматов в одной колонке

pd.to_datetime(df["delivered_at"]) # ошибка или тихо перепутанные день и месяц
d1 = pd.to_datetime(s, format="%Y-%m-%d %H:%M", errors="coerce") d2 = pd.to_datetime(s, format="%d.%m.%Y %H:%M", errors="coerce") d1.fillna(d2)

Явно указывай формат и проверяй, сколько не прочиталось. «03.08» может быть и 3 августа, и 8 марта.

3

.dt.days теряет часы

(a - b).dt.days отбрасывает часы: 1 день 23 часа превращается в 1. Для сроков доставки считай часы через .dt.total_seconds() / 3600.

4

Пустые даты в среднем

Посылки «в пути» (NaT) не попадают в среднее время доставки. Если их много, среднее получится слишком оптимистичным — пиши, сколько посылок ещё не доставлено.

5

Понедельник — это 0

dayofweek считает с нуля: 0 — понедельник, 5 — суббота, 6 — воскресенье. Выходные — это >= 5, а не >= 6.

Шпаргалка урока: 8 строк про даты

  1. pd.to_datetime(s) — текст → дата
  2. pd.to_datetime(s, format="%d.%m.%Y", errors="coerce") — свой формат, ошибки → NaT
  3. d1.fillna(d2) — склеить две попытки чтения
  4. s.dt.month / .dt.hour / .dt.dayofweek — части даты
  5. s.dt.to_period("M") — округлить до месяца
  6. (b - a).dt.total_seconds() / 3600 — разница в часах
  7. df[df["d"] >= "2026-09-01"] — фильтр по дате
  8. s.isna().sum() — сколько дат не прочиталось
05 · Самопроверка · 20 XP

Квиз за 3 минуты

1. Какой тип у колонки с датой сразу после read_csv?

read_csv сам не превращает текст в даты. Нужен pd.to_datetime или parse_dates при чтении.

2. Что делает errors="coerce"?

coerce = «заставь»: всё, что не читается, становится пустой датой NaT, и код не падает.

3. Какой номер у субботы в .dt.dayofweek?

Счёт с понедельника = 0, значит суббота — 5, воскресенье — 6.

4. Как получить разницу двух дат в часах?

total_seconds() даёт весь промежуток в секундах, деление на 3 600 — часы. .dt.days отбросит часы.

5. Что вернёт .dt.to_period("M") для 2026-07-03 14:22?

Период «месяц»: только год и месяц, удобно для отчётов по месяцам.
