Типы данных: числа, строки, категории и память

pandas сам угадывает, что лежит в колонке: числа, текст или даты. И часто ошибается: одна строка «ошибка» в колонке суммы — и вся колонка становится текстом, а сумма «склеивается» вместо сложения. Сегодня учимся видеть такие ошибки и приводить колонки к правильным типам.

02 · Теория

Тип колонки — это ярлык на коробке

Простыми словами

Представь склад с коробками. На каждой коробке ярлык: «гвозди», «шурупы», «краска». Работник читает ярлык и знает, что с коробкой делать. В pandas у каждой колонки тоже есть ярлык — тип данных, по-английски dtype (data type). Он говорит pandas, что можно делать со значениями: складывать, сравнивать, брать первые буквы.

  • int64 — целые числа (1, 25, 500001). «64» — сколько места в памяти занимает одно число (64 бита). Пустую клетку NaN хранить не умеет.
  • float64 — дробные числа (42.0, 3.14). Умеет хранить NaN — поэтому колонка возраста с пропусками стала float, хотя возраст целый.
  • Int64 (с большой буквы) — целые числа, которые умеют хранить пропуск. Пропуск показывается как <NA>.
  • str — текст. В pandas 3.0 это тип по умолчанию для строк. Плюс (+) для текста — это склейка: «12» + «3» = «123», а не 15.
  • bool — только True или False. Как галочка в анкете.
  • category — текст с маленьким набором повторяющихся значений (app, pos, web, atm). pandas хранит список вариантов один раз, а в строках — только номер варианта. Памяти нужно в десятки раз меньше.

Главная ловушка дня: одна плохая клетка портит тип всей колонки. В колонке суммы 968 нормальных чисел и одна запись «ошибка» — и pandas честно читает всю колонку как текст. Теперь sum() склеивает строки.

Настоящие строки файла. Розовые подписи — тип, который pandas угадал. Жёлтая колонка amount выглядит как числа, но это текст.

03 · Теория

Семь приёмов: увидеть тип, починить тип, сэкономить память

Как читать код
  • df.info() — метод без аргументов, пустые скобки обязательны. Печатает сам, поэтому print() вокруг не нужен.
  • pd.to_numeric(df["amount"], errors="coerce") — функция из pd, а не метод колонки. Внутрь передаём колонку и аргумент errors («что делать с ошибками»). "coerce" — превратить в NaN. Без него будет ошибка.
  • .astype("Int64") — тип пишется строкой в кавычках. Большая буква I важна: "int64" и "Int64" — разные типы.
  • .astype(bool), .astype(str) — можно без кавычек: это встроенные типы Python.
  • df.astype({"client_id": "str", "is_premium": "bool"}) — словарь: слева имя колонки, справа тип. Меняет несколько колонок за раз.
  • pd.CategoricalDtype(["silver", "gold", "platinum"], ordered=True) — создаём свой тип: список вариантов в нужном порядке и флаг «порядок важен».
  • memory_usage(deep=True) — сколько байт занимает колонка. deep=True — «посчитай и сам текст, а не только ссылки на него».

Каждый вывод ниже получен реальным запуском pandas 3.0 на файле Kapital Pay. Твои цифры должны совпасть (кроме байтов памяти — они зависят от того, установлен ли pyarrow).

1. info() — паспорт типов.
import pandas as pd

df = pd.read_csv("kapital_payments.csv")
df.info()

Простыми словами: 6 колонок текстовые (str), 3 целые (int64), 1 дробная (float64). Подозрительно: amount — str, хотя это деньги. И amount 991 non-null: 9 пустых — это «n/a», read_csv сам считает такую запись пропуском.

2. Почему сумма — «склейка».
print(df["amount"].head(3))
print(str(df["amount"].sum())[:40])
0 1019000 1 171000 2 198000 Name: amount, dtype: str 1019000171000198000267000149000164000590

Простыми словами: внизу написано dtype: str — это текст. Для текста «+» значит «приклеить»: «1019000» + «171000» = «1019000171000». Мы напечатали только первые 40 символов, а вся строка длиной в тысячи цифр.

3. pd.to_numeric — TRY_CAST.
amount_num = pd.to_numeric(df["amount"], errors="coerce")
print(amount_num.dtype, amount_num.isna().sum())
print(amount_num.sum())
float64 32 346828000.0

Простыми словами: теперь тип float64 и сумма — настоящее число: 346 828 000 сум. Пустых стало 32: 9 «n/a» были пустыми и раньше, а ещё 23 значения («-», «нет», «ошибка») не превратились в число и стали NaN. Их надо посчитать и показать стейкхолдеру, а не молча выбросить.

4. Int64 — целые числа с пропусками.
age = df["age"].astype("Int64")
age.head(3)
0 62 1 62 2 31 Name: age, dtype: Int64

Простыми словами: было 62.0, стало 62 — без лишней «.0». Тип Int64 с большой буквы. Если написать astype(int), будет ошибка IntCastingNaNError: у 23 клиентов нет возраста, а обычный int64 не умеет хранить пустоту.

5. bool — флаг вместо 0/1.
df["is_premium"].astype(bool).value_counts()
is_premium False 771 True 229 Name: count, dtype: int64

Простыми словами: 0 стал False, 1 стал True. Премиум-платежей 229 из 1000. Зачем менять? С bool можно сразу фильтровать: df.loc[df["is_premium"]], а ~ (тильда) переворачивает: df.loc[~df["is_premium"]] — не премиум.

6. category — экономия памяти.
before = df["channel"].memory_usage(deep=True)
after = df["channel"].astype("category").memory_usage(deep=True)
print(before, after, round(before / after))
52132 1340 39

Простыми словами: колонка channel занимала 52 132 байта, после category — 1 340, в 39 раз меньше. В колонке 1000 строк, но разных значений всего 4. Category хранит 4 слова один раз, а в строках — номера 0–3. На миллионе строк это разница между «тормозит» и «летает».

7. Упорядоченная категория — ENUM.
tier_type = pd.CategoricalDtype(["silver", "gold", "platinum"], ordered=True)
print((df["tier"] >= "gold").sum())
tier = df["tier"].astype(tier_type)
print((tier >= "gold").sum())
1000 400

Простыми словами: как текст, «silver» >= «gold» — True, потому что по алфавиту s идёт после g. Поэтому первая строка насчитала все 1000. После упорядоченной категории pandas знает правильный порядок silver < gold < platinum, и ответ честный: 400 (gold 273 + platinum 127).

История про копилку: числа и надписи

Три друга записали на бумажках, сколько тысяч сум положили в копилку: «5», «12», «ноль». Мама просит сложить. Если считать бумажки надписями, их можно только приклеить друг к другу: «5» + «12» = «512». Это не деньги, а надпись.

«5» → 5 · «12» → 12«ноль» → NaN (розовый)

Если сначала превратить надписи в числа (это и есть to_numeric), получится 5 + 12 = 17. Бумажка «ноль» написана словом — превратить её нельзя, она становится пустой (NaN). Сумма 17 верна для двух бумажек, а про третью надо спросить друга. Так и с 23 «мусорными» суммами у Шерзода: посчитать, сколько их, и сказать об этом.

Правило аналитика. Новый файл → сначала df.info(). Если колонка с деньгами, количеством или датой имеет тип str, не считай по ней ничего, пока не найдёшь причину.
04 · Ловушки

Пять ошибок, на которых спотыкается большинство

1

sum() по тексту не падает

df["amount"].sum() # '1019000171000198000…'
pd.to_numeric(df["amount"], errors="coerce").sum() # 346828000.0

Нет ошибки — не значит верно. Перед суммой проверь dtype колонки.

2

astype(float) на грязной колонке

df["amount"].astype(float) # ValueError: could not convert string to float: '-'
pd.to_numeric(df["amount"], errors="coerce")

astype требует, чтобы подходило каждое значение. Для грязного текста — to_numeric с coerce.

3

coerce молча прячет мусор

amount = pd.to_numeric(df["amount"], errors="coerce") # и дальше считаем, как будто всё хорошо
bad = df["amount"].notna() & amount.isna() print(bad.sum()) # 23 — сказать об этом стейкхолдеру

coerce превращает «ошибка» в NaN без предупреждения. Всегда считай, сколько значений потерял.

4

int64 не хранит NaN

df["age"].astype(int) # IntCastingNaNError
df["age"].astype("Int64") # пропуски станут <NA>

Маленькая i — обычный int64, большая I — целые с пропусками. Одна буква меняет всё.

5

Сравнение уровней по алфавиту

(df["tier"] >= "gold").sum() # 1000: «silver» > «gold» по алфавиту
tier_type = pd.CategoricalDtype(["silver", "gold", "platinum"], ordered=True) (df["tier"].astype(tier_type) >= "gold").sum() # 400

Текст сравнивается буква за буквой. Если у значений есть смысловой порядок, задай его через ordered=True.

Шпаргалка урока: 8 строк, которые надо помнить

  1. df.info() / df.dtypes — первым делом: какие типы
  2. pd.to_numeric(df["x"], errors="coerce") — текст → число, мусор → NaN
  3. (df["x"].notna() & num.isna()).sum() — сколько мусора потерял coerce
  4. df["age"].astype("Int64") — целые с пропусками
  5. df["flag"].astype(bool) / df["id"].astype(str) — флаг и ID
  6. df.astype({"a": "str", "b": "bool"}) — несколько колонок разом
  7. df["c"].astype("category") — мало разных значений → меньше памяти
  8. pd.CategoricalDtype([...], ordered=True) — порядок уровней, как ENUM
05 · Самопроверка · 20 XP

Квиз за 3 минуты

1. Колонка amount имеет тип str. Что вернёт df["amount"].sum()?

Для текста «+» — это склейка. pandas не падает, поэтому ошибку легко не заметить.

2. Чем pd.to_numeric(s, errors="coerce") отличается от s.astype(float)?

coerce — «заставить»: то, что нельзя превратить в число, становится NaN. Строки не удаляются.

3. Почему df["age"].astype(int) падает?

Нужен тип "Int64" с большой I — он хранит пропуск как <NA>.

4. Когда тип category экономит память сильнее всего?

4 канала на 1000 строк: слова хранятся один раз, в строках — номера. channel: 52 132 → 1 340 байт.

5. tier — str со значениями silver, gold, platinum. Сколько вернёт (df["tier"] >= "gold").sum()?

Текст сравнивается по алфавиту: «platinum» и «silver» оба после «gold». Нужна упорядоченная категория.
