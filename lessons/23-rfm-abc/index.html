02 · Теория

RFM: три вопроса о каждом клиенте

Простыми словами

Представь кофейню. Постоянный гость, который заходит каждый день, — самый ценный. Гость, который раньше ходил часто, а теперь пропал на два месяца, — тот, кого пора вернуть. RFM описывает каждого клиента тремя числами:

  • R — Recency (свежесть): сколько дней прошло с последней покупки. Меньше — лучше.
  • F — Frequency (частота): сколько раз покупал.
  • M — Monetary (деньги): сколько всего потратил.
  • Каждое число превращают в оценку 1–3, а потом по оценкам дают сегменту понятное имя: «Чемпионы», «Уходящие»…
  • qcut делит клиентов на группы поровну по количеству (треть, треть, треть). cut делит по границам, которые задаёшь сам (1 покупка, 2 покупки, 3 и больше).
1. Таблица RFM.
rfm = df.groupby("customer_id").agg(last=("order_date", "max"),
                                    frequency=("order_id", "count"),
                                    monetary=("amount", "sum"))
rfm["recency"] = (today - rfm["last"]).dt.days
rfm[["recency", "frequency", "monetary"]].head()

Простыми словами: одна строка — один клиент: сколько дней назад он покупал последний раз, сколько раз и на какую сумму.

2. qcut и cut на игрушечном примере. 9 клиентов, сколько дней назад покупали.
days = pd.Series([3, 8, 15, 20, 40, 60, 90, 150, 300])

    "дней_назад": days,
    "qcut_на_трети": pd.qcut(days, 3, labels=["свежие", "средние", "давние"]),
    "cut_по_границам": pd.cut(days, [0, 30, 90, np.inf], labels=["до месяца", "1–3 месяца", "дольше"]),

Простыми словами: qcut сам ищет границы так, чтобы в каждой группе было поровну людей: по 3 клиента. cut использует твои границы (30 и 90 дней), и людей в группах может быть сколько угодно: здесь 4, 3 и 2. Когда данные «перекошены» (как частота покупок: у большинства одна), поровну поделить нельзя — тогда берут cut.

3. Оценки R и F на настоящих данных.
rfm["R"] = pd.qcut(rfm["recency"], 3, labels=[3, 2, 1]).astype(int)
rfm["F"] = pd.cut(rfm["frequency"], [0, 1, 2, np.inf], labels=[1, 2, 3]).astype(int)
print(rfm["R"].value_counts().sort_index())
rfm["F"].value_counts().sort_index()
R 1 217 2 213 3 220 Name: count, dtype: int64 F 1 166 2 143 3 341 Name: count, dtype: int64

Простыми словами: R: самая свежая треть клиентов получила 3, самая давняя — 1. Метки идут наоборот (3, 2, 1), потому что меньше дней — лучше. F: у большинства одна покупка, поэтому частоту делим по границам, а не на трети.

4. Имена сегментов: правила сверху вниз. Приём для задачи 4.
toy = pd.DataFrame({"R": [3, 3, 1, 3, 2], "F": [3, 1, 3, 2, 1]}, index=["Аня", "Бобур", "Вера", "Гуля", "Дима"])
rules = [(toy["R"] == 3) & (toy["F"] == 3), toy["F"] == 3, (toy["R"] == 1) & (toy["F"] >= 2), (toy["R"] == 3) & (toy["F"] == 1)]
toy["segment"] = np.select(rules, ["Чемпионы", "Лояльные", "Уходящие", "Новые"], default="Остальные")
toy

Простыми словами: np.select проверяет правила по порядку и берёт первое подходящее. У Веры F = 3, поэтому она «Лояльная», хотя подходит и под «Уходящие» (R = 1): правило «Лояльные» стоит выше. У Ани подходят и «Чемпионы», и «Лояльные», но «Чемпионы» — первое правило. Гуля и Дима не подошли ни под одно правило и получили default — «Остальные».

03 · Теория

ABC: какие товары дают выручку

Как устроен ABC-анализ
  • Сортируем товары по выручке от большей к меньшей.
  • Считаем накопленную долю: первый товар — 15%, первые два — 27%, … последний — 100%. Это cumsum() / sum().
  • A — товары, которые вместе дают первые 80% выручки, B — следующие 15%, C — оставшиеся 5%.
  • Обычно группа A — это меньшинство товаров. Их всегда держат в наличии.
5. ABC на игрушечном примере. 5 товаров.
toy = pd.Series({"диван": 500, "шкаф": 300, "стол": 120, "стул": 50, "полка": 30}, name="выручка")
share = toy.cumsum() / toy.sum()
pd.DataFrame({
    "выручка": toy,
    "накоплено": toy.cumsum(),
    "накопленная_доля_%": (share * 100).round(1),
    "класс": np.where(share <= 0.8, "A", np.where(share <= 0.95, "B", "C")),
})
выручка накоплено накопленная_доля_% класс диван 500 500 50.0 A шкаф 300 800 80.0 A стол 120 920 92.0 B стул 50 970 97.0 C полка 30 1000 100.0 C

Простыми словами: всего 1 000. Диван один даёт 50%, диван + шкаф — 80%: это класс A, всего 2 товара из 5. Стол дотягивает до 92% — класс B. Стул и полка вместе — последние 8% денег, класс C. Товары уже стоят от дорогого к дешёвому; на настоящих данных это делает sort_values.

6. Накопленная доля выручки. Теперь по мебели.
prod = df.groupby("product")["amount"].sum().sort_values(ascending=False)
cum = (prod.cumsum() / prod.sum() * 100).round(1)
cum.head(8)
product P022 24.6 P011 45.8 P005 50.6 P004 54.9 P058 58.8 P016 62.7 P045 66.0 P001 68.4 Name: amount, dtype: float64

Простыми словами: первые несколько товаров уже дают большую часть денег. Там, где накопленная доля переходит 80%, заканчивается группа A.

Правило аналитика. Сегменты нужны, чтобы действовать. Для каждого сегмента сразу пиши, что с ним делать: чемпионов — благодарить и просить отзывы, уходящих — возвращать персональным предложением, новых — довести до второй покупки.
04 · Ловушки

Четыре ловушки сегментации

1

qcut на числах с повторами

pd.qcut(rfm["frequency"], 3) # ValueError: Bin edges must be unique
pd.cut(rfm["frequency"], [0, 1, 2, np.inf], labels=[1, 2, 3])

Если у половины клиентов одна покупка, «трети» по частоте не получаются. Для таких колонок задавай границы сам через cut.

2

Перевёрнутая шкала Recency

Для Recency меньше — лучше. Если дать самым свежим оценку 1, «Чемпионами» станут те, кто давно ушёл. Поэтому labels=[3, 2, 1].

3

Порядок условий в np.select

np.select берёт первое подходящее условие. Если «Лояльные» (F = 3) стоят раньше «Чемпионов» (R = 3 и F = 3), чемпионов не останется. Сначала самые узкие условия.

4

ABC без сортировки

Накопленная доля имеет смысл только после сортировки от большего к меньшему. Без сортировки в группу A попадут случайные товары.

Шпаргалка урока: RFM и ABC

  1. (today - rfm["last"]).dt.days — Recency в днях
  2. pd.qcut(s, 3, labels=[3, 2, 1]) — трети по количеству
  3. pd.cut(s, [0, 1, 2, np.inf], labels=[1, 2, 3]) — группы по своим границам
  4. np.select([усл1, усл2], ["имя1", "имя2"], default="прочие") — имена сегментов
  5. prod.sort_values(ascending=False).cumsum() / prod.sum() — накопленная доля
  6. np.where(cum <= 0.8, "A", np.where(cum <= 0.95, "B", "C")) — классы ABC
05 · Самопроверка · 20 XP

Квиз за 3 минуты

1. Что такое Recency?

Recency — свежесть: как давно клиент покупал последний раз.

2. Чем qcut отличается от cut?

qcut — квантили (трети, четверти), cut — интервалы, которые ты задаёшь.

3. Почему для Recency используют labels=[3, 2, 1]?

Первая треть — самые маленькие значения (свежие клиенты), им даём оценку 3.

4. Что такое товары группы A?

ABC делит товары по накопленной доле выручки: A — первые 80%.

5. В np.select условия «F == 3» и «R == 3 and F == 3». Какое ставить первым?

Сначала более узкое условие, иначе все чемпионы попадут в «Лояльных».
