01 · Брифинг

Отчёт по бонусам считается 40 минут

ООтабек разработчик программы лояльности · 13:15

Привет! Наш скрипт считает бонус для каждой покупки в цикле. На тестовых 6 000 строк — секунда, а на настоящих 30 миллионах покупок ночной отчёт идёт 40 минут и иногда падает по памяти. Можешь переписать расчёт по-человечески?

▤ bonus_tx.csv · 6 000 тестовых покупок

Правила бонусов: базовая ставка по категории (Продукты 1%, АЗС 2%, Кафе 5%, Электроника 3%), множитель уровня клиента (bronze ×1, silver ×1,5, gold ×2), в выходные в Кафе ставка выше на 1 процентный пункт, бонус за одну покупку — не больше 50 000 сум. Задачи можно решать прямо на этой странице.

Скачать bonus_tx.csv6 000 строк · 225 КБ

Как открыть файл у себя в Jupyter. Положи скачанный файл в ту же папку, где лежит ноутбук, и выполни в первой ячейке:

import pandas as pd
import numpy as np
import time
df = pd.read_csv("bonus_tx.csv")
RATE = {"Продукты": 0.01, "АЗС": 0.02, "Кафе": 0.05, "Электроника": 0.03}
MULT = {"bronze": 1.0, "silver": 1.5, "gold": 2.0}

На этой странице ничего скачивать не нужно: в задачах таблица уже загружена в df.

02 · Теория

Строка за строкой или вся колонка сразу

Простыми словами

Представь кассира, который пробивает чеки. Можно звать покупателей по одному, спрашивать, что у него, и считать в уме — это цикл. А можно положить все товары на ленту, и сканер посчитает всё разом — это векторизация.

  • Цикл for и apply(axis=1) выполняют Python-код для каждой строки отдельно. На миллионах строк это очень медленно.
  • Векторные операции (df["a"] * df["b"], map, np.where) работают с колонкой целиком: внутри pandas и numpy это быстрый код на C.
  • map(словарь) — «замени каждое значение по словарю»: категорию на ставку.
  • np.where(условие, если_да, если_нет) — «если… то… иначе…» для всей колонки сразу. np.select — то же для нескольких условий.
  • clip(upper=…) — «не больше чем…».
1. Медленно: цикл по строкам.
start = time.perf_counter()
bonuses = []
for _, row in df.iterrows():
    rate = RATE[row["category"]]
    if row["is_weekend"] and row["category"] == "Кафе":
        rate += 0.01
    bonuses.append(min(row["amount"] * rate * MULT[row["client_level"]], 50_000))
print(round(sum(bonuses)), f"{time.perf_counter() - start:.3f} сек")
29432968 0.251 сек

Простыми словами: правильно, но каждая из 6 000 строк обрабатывается отдельно. На 30 миллионах строк это и есть «40 минут».

2. Быстро: векторный расчёт.
start = time.perf_counter()
rate = df["category"].map(RATE) + np.where(df["is_weekend"] & (df["category"] == "Кафе"), 0.01, 0)
bonus = (df["amount"] * rate * df["client_level"].map(MULT)).clip(upper=50_000)
print(round(bonus.sum()), f"{time.perf_counter() - start:.3f} сек")
29432968 0.006 сек

Простыми словами: та же сумма бонусов, но в сотни раз быстрее: три операции над колонками вместо 6 000 маленьких расчётов.

3. Тот же расчёт по шагам на 5 покупках. Видно, что делает каждая операция.
few = df.head(5)[["category", "is_weekend", "client_level", "amount"]].copy()
few["ставка"] = few["category"].map(RATE)
few["надбавка"] = np.where(few["is_weekend"] & (few["category"] == "Кафе"), 0.01, 0)
few["множитель"] = few["client_level"].map(MULT)
few["бонус"] = few["amount"] * (few["ставка"] + few["надбавка"]) * few["множитель"]
few["с_потолком"] = few["бонус"].clip(upper=50_000)
few

Простыми словами: map подставил ставку по категории и множитель по уровню клиента. np.where поставил +0,01 только там, где выходной и кафе. Последняя колонка — clip: всё, что больше 50 000, стало бы 50 000 (в этих пяти покупках бонусы маленькие, потолок не сработал). Каждая строка кода — одна колонка сразу для всех покупок, без цикла.

4. np.select: несколько условий по порядку. Приём для задачи 5.
amounts = pd.Series([20_000, 49_999, 50_000, 300_000, 900_000])
pd.DataFrame({
    "сумма": amounts,
    "размер": np.select([amounts < 50_000, amounts < 500_000], ["мелкая", "средняя"], default="крупная"),
})
сумма размер 0 20000 мелкая 1 49999 мелкая 2 50000 средняя 3 300000 средняя 4 900000 крупная

Простыми словами: условия проверяются сверху вниз: сначала «меньше 50 000», потом «меньше 500 000». 300 000 не прошла первое условие, но прошла второе — «средняя». Всё, что не подошло ни под одно условие, получает default — «крупная».

5. Почему дроби сравнивают через np.allclose. Приём для задачи 6.
print(0.1 + 0.2 == 0.3)
print(0.1 + 0.2)
print(np.allclose(0.1 + 0.2, 0.3))
False 0.30000000000000004 True

Простыми словами: компьютер хранит дроби чуть-чуть неточно, поэтому 0,1 + 0,2 получается 0,30000000000000004, и обычное «равно» говорит False. Когда сравнивают результаты двух способов расчёта, используют np.allclose — «равны с точностью до крошечной погрешности».

03 · Теория

Меньше памяти: category и только нужные колонки

Как читать код
  • memory_usage(deep=True) — сколько байт занимает каждая колонка. deep=True считает и текст честно.
  • category — тип для колонок, где мало разных значений и много повторов (уровень клиента, город). pandas хранит каждое слово один раз, а в строках — короткие номера.
  • read_csv(..., usecols=[...]) — читать только нужные колонки. chunksize=100_000 — читать огромный файл кусками.
  • Parquet — формат файлов для больших таблиц: читается быстрее CSV и хранит типы. df.to_parquet("x.parquet"), pd.read_parquet("x.parquet") (нужна библиотека pyarrow).
6. Сколько памяти занимает таблица.
before = df.memory_usage(deep=True)
small = df.astype({"client_level": "category", "category": "category"})
after = small.memory_usage(deep=True)
pd.DataFrame({"before_kb": (before / 1024).round(1), "after_kb": (after / 1024).round(1)})
before_kb after_kb Index 0.1 0.1 tx_id 46.9 46.9 client_level 80.9 5.9 category 120.4 5.9 amount 46.9 46.9 is_weekend 5.9 5.9

Простыми словами: текстовые колонки с повторами после category занимают в разы меньше. Числа не изменились.

7. Читать кусками. Сумма покупок без загрузки всего файла в память.
total = 0
for chunk in pd.read_csv("bonus_tx.csv", usecols=["amount"], chunksize=2_000):
    total += chunk["amount"].sum()
total
967570800

Простыми словами: файл прочитан тремя кусками по 2 000 строк, в памяти одновременно был только один кусок и только одна колонка.

Правило аналитика. Если пишешь for … in df.iterrows() или apply(…, axis=1), остановись и спроси: «а можно это колонкой?». Почти всегда можно.
04 · Ловушки

Четыре ловушки скорости

1

apply(axis=1) — тот же цикл

df.apply(lambda r: r["amount"] * RATE[r["category"]], axis=1)
df["amount"] * df["category"].map(RATE)

apply по строкам выглядит короче цикла, но работает почти так же медленно: функция вызывается для каждой строки.

2

and / or вместо & / |

np.where(df["is_weekend"] and df["category"] == "Кафе", 0.01, 0) # ValueError
np.where(df["is_weekend"] & (df["category"] == "Кафе"), 0.01, 0)

Для колонок — только &, | и скобки вокруг каждого условия (урок 2).

3

map с ключом, которого нет в словаре

Если в данных встретится категория, которой нет в словаре, map даст NaN, и бонус молча станет пустым. После map проверь: rate.isna().sum().

4

category и новые значения

В колонку типа category нельзя записать значение, которого нет в её списке категорий. Для колонок, которые часто меняются, category не подходит.

Шпаргалка урока: быстрый код

  1. df["cat"].map(словарь) — замена по словарю
  2. np.where(усл, a, b) — если… то… иначе для колонки
  3. np.select([усл1, усл2], [a, b], default=c) — несколько условий
  4. s.clip(lower=0, upper=50_000) — ограничить значения
  5. df.memory_usage(deep=True).sum() — память таблицы
  6. df.astype({"col": "category"}) — меньше памяти для повторяющегося текста
  7. pd.read_csv(f, usecols=[...], chunksize=100_000) — читать нужное и кусками
  8. time.perf_counter() — засечь время
05 · Самопроверка · 20 XP

Квиз за 3 минуты

1. Почему apply(..., axis=1) медленный?

apply по строкам — это, по сути, тот же цикл Python.

2. Что сделает df["category"].map({"Кафе": 0.05}) для строки «АЗС»?

Значений, которых нет в словаре, map превращает в NaN.

3. Как ограничить бонус сверху 50 000?

clip(upper=…) заменяет всё, что больше порога, на порог. Фильтр удалил бы строки.

4. Для какой колонки тип category полезнее всего?

category экономит память, когда разных значений мало, а повторов много.

5. Что делает chunksize в read_csv?

Каждый кусок обрабатывают по очереди, и весь файл не нужно держать в памяти.
